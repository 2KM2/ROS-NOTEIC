# RViz 颜色：OPEN / CLOSED / 路径

这是图搜索每一步的**工作状态**，不是地图本身。  
灰格子是障碍；绿 / 蓝 / 红是算法脑子里的三类格子。

```text
还没见过的空地           白色（OccupancyGrid 空闲）
已经发现、排队等处理     OPEN    绿
已经取出、处理完毕       CLOSED  蓝
这一步正在处理的格子     当前    红
真正要走的那一条         路径    橙
任务起点 / 终点          紫球 / 青绿球
```

## OPEN（绿）

frontier，待处理集合。算法已经走到它旁边、把它放进队列 / 栈 / 堆了，但还没展开邻居。

- BFS：还在 FIFO 队列里的格子
- DFS：还在栈里的格子
- Dijkstra / A*：堆里还没定为最终最短的格子

## CLOSED（蓝）

已经弹出并处理过。邻居都看过了，`g` / 父亲不再改（Dijkstra / A* 第一次 CLOSED 时，`g` 就是最短代价）。

- BFS：蓝会一圈圈铺成菱形（4 邻域，曼哈顿等距面）
- DFS：蓝常常是一条细线扎出去
- A*：蓝通常比 Dijkstra 小（`h` 把搜索拉向终点）

蓝的是**探过的所有格子**，通常比最终路径多很多。

## 当前（红）

这一步从 OPEN 里取出的那一个格子。取出后它会变成 CLOSED，并把还没进过集合的邻居丢进 OPEN。  
按 `n` 就是看红点怎么跳。

起点刚开始：只有起点在 OPEN。第一按 `n`：红点在起点，然后它变蓝，四周变绿。之后红点总在绿边上走，蓝区域慢慢变大，直到红点落到终点。

## 起终点和最终路径

- **紫球 = 起点**，**青绿球 = 终点**。这是任务，不是搜索状态。  
  RViz 里可用 `2D Pose Estimate` / `2D Nav Goal` 改。
- **橙线 = 最终路径**：搜索成功结束后，从终点顺着 `parent` 一直走回起点，再反转得到的格子序列。  
  不是蓝格子的轮廓。橙线才是「实际要走的那一条」。

## 对照

```text
蓝 CLOSED  = 为了找到路，算法扫过的区域（越大越「笨」/ 越不带启发）
绿 OPEN    = 下一圈准备扫的前沿
红 当前    = 这一步正在扫谁
橙 路径    = 扫完以后真正要走的那串格子
```

所以：

- A* 的蓝通常比 Dijkstra 小
- DFS 的蓝可能又长又歪，橙线往往也不是最短
- 4 邻域下 BFS 和 Dijkstra 的橙线代价相同
- 8 邻域下 Dijkstra / A* 的橙线可以比 BFS 更短（按 `v` 切换邻域）
