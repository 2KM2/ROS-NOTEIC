# 激光数据处理流程讲解

本文讲解 `LidarMotionUndistortion.cpp` 中 `ScanCallBack()` 的处理过程：接收一帧激光数据、校验和清洗数据、查询 TF 位姿、执行运动畸变校正，并把校正前后的点云发布到 RViz。

- 源文件：`../LaserUndistortion_ws/src/LaserUndistortion/src/LidarMotionUndistortion.cpp`
- 核心回调：`ScanCallBack()`（第 40 行）
- 原始点云话题：`/laser_motion/raw_cloud`
- 校正点云话题：`/laser_motion/corrected_cloud`

---

## 1. 整体处理流程

```text
champion_scan 激光消息到达
        │
        ▼
1. 记录第一束激光的时间 startTime
        │
        ▼
2. 校验 ranges / angles 数量和数据有效性
        │
        ▼
3. 根据 time_increment 计算最后一束激光时刻 endTime
        │
        ▼
4. 清洗无效距离和非法角度，保持激光束的原有时间顺序
        │
        ▼
5. 查询第一束激光时刻的 odom → base_laser 位姿
        │
        ▼
6. 保存未校正扫描数据副本
        │
        ▼
7. 分段查询 TF，对扫描过程中的机器人运动做畸变校正
        │
        ▼
8. 将原始/校正数据发布为 odom 坐标系下的点云
```

---

## 2. 回调函数的作用

回调函数入口如下：

```cpp
void ScanCallBack(const champion_nav_msgs::ChampionNavLaserScanPtr& scan_msg)
```

当节点订阅的话题 `champion_scan` 收到一帧 `ChampionNavLaserScan` 消息时，ROS 会调用该函数。

这类激光消息中，重点字段包括：

| 字段 | 含义 |
|---|---|
| `header.stamp` | 第一束激光的采集时刻 |
| `ranges[i]` | 第 `i` 束激光测得的距离 |
| `angles[i]` | 第 `i` 束激光对应的扫描角度 |
| `time_increment` | 相邻两束激光之间的采样时间间隔 |

每一束激光不仅有距离和角度，还隐含一个采集时间：

$$
t_i = t_{start} + i \cdot \Delta t
$$

其中：

- $t_i$：第 $i$ 束激光的采样时刻；
- $t_{start}$：第一束激光的采样时刻；
- $\Delta t$：`time_increment`；
- $i$：激光束下标，从 `0` 开始。

---

## 3. 获取扫描起始时间

```cpp
ros::Time startTime, endTime;
startTime = scan_msg->header.stamp;
```

这里将消息时间戳记录为 `startTime`。

本程序采用的约定是：**消息时间戳表示第一束激光的采集时刻**。因此，第 `0` 束激光对应 `startTime`，并不是整帧扫描结束的时间。

接着将 ROS 消息拷贝到局部变量：

```cpp
champion_nav_msgs::ChampionNavLaserScan laserScanMsg = *scan_msg;
```

后续只读取该局部副本，避免意外修改回调传入的原始 ROS 消息。

---

## 4. 校验激光束数量和数组匹配关系

```cpp
if (laserScanMsg.ranges.size() >
    static_cast<std::size_t>(std::numeric_limits<int>::max()))
{
    ROS_WARN("Laser scan has too many beams");
    return;
}

const int beamNum = static_cast<int>(laserScanMsg.ranges.size());

if (beamNum == 0 || laserScanMsg.angles.size() != laserScanMsg.ranges.size())
{
    ROS_WARN("Invalid laser scan data");
    return;
}
```

这部分有两层检查：

1. **安全转换检查**：`ranges.size()` 的类型是无符号的 `std::size_t`，而后续循环使用 `int` 下标。先确认数据量不超过 `int` 上限，再转换，避免溢出。
2. **数据完整性检查**：
   - `beamNum == 0`：当前帧没有激光束；
   - `angles.size() != ranges.size()`：距离数组和角度数组不能一一对应。

只有每个 `ranges[i]` 都能对应到 `angles[i]`，才能将该束激光转换为点云坐标。

---

## 5. 计算最后一束激光的采集时刻

```cpp
endTime = startTime + ros::Duration(
    laserScanMsg.time_increment * static_cast<double>(beamNum - 1));
```

如果一帧有 `N` 束激光，则下标范围为 `0` 到 `N - 1`：

```text
第 0 束激光：startTime
第 1 束激光：startTime + 1 × time_increment
...
第 N - 1 束：startTime + (N - 1) × time_increment
```

因此：

$$
t_{end} = t_{start} + (N - 1) \cdot \Delta t
$$

注意这里是 `beamNum - 1`，而不是 `beamNum`。因为第 `0` 束激光就在 `startTime` 时刻，并没有经过一个时间间隔。

---

## 6. 清洗激光数据，并保持时间顺序

```cpp
std::vector<double> angles;
std::vector<double> ranges;
angles.reserve(beamNum);
ranges.reserve(beamNum);

for (int i = 0; i < beamNum; ++i)
{
    double lidar_dist = laserScanMsg.ranges[i];
    double lidar_angle = laserScanMsg.angles[i];

    if (lidar_dist < 0.05 || !std::isfinite(lidar_dist))
        lidar_dist = 0.0;

    if (!std::isfinite(lidar_angle))
    {
        ROS_WARN_THROTTLE(1.0, "Laser scan contains non-finite angles");
        lidar_dist = 0.0;
        lidar_angle = 0.0;
    }

    ranges.push_back(lidar_dist);
    angles.push_back(lidar_angle);
}
```

### 6.1 预分配内存

```cpp
angles.reserve(beamNum);
ranges.reserve(beamNum);
```

`reserve()` 提前分配足够容量，避免在循环的 `push_back()` 过程中多次扩容和复制数据。

### 6.2 过滤无效距离

```cpp
if (lidar_dist < 0.05 || !std::isfinite(lidar_dist))
    lidar_dist = 0.0;
```

以下距离会被视为无效：

- 小于 `0.05 m` 的距离：通常处于雷达盲区、测量噪声区或不可靠区域；
- `NaN`：不是一个数；
- `Inf` / `-Inf`：无穷大或无穷小。

程序暂时把这些距离统一写成 `0.0`，在后续发布点云时会跳过它们。

### 6.3 过滤非法角度

```cpp
if (!std::isfinite(lidar_angle))
{
    ROS_WARN_THROTTLE(1.0, "Laser scan contains non-finite angles");
    lidar_dist = 0.0;
    lidar_angle = 0.0;
}
```

如果角度不合法，后续的 `sin()`、`cos()` 坐标转换无法可靠执行。因此：

- 用 `ROS_WARN_THROTTLE(1.0, ...)` 报警，最多每秒打印一次，避免日志刷屏；
- 将距离置为 `0.0`，保证该束激光不会参与点云生成；
- 将角度设为 `0.0`，防止非法值继续向后传播。

### 6.4 为什么不能打乱激光束顺序？

第 `i` 个数组元素同时对应：

```text
ranges[i]  → 第 i 束激光的距离
angles[i]  → 第 i 束激光的角度
时间       → startTime + i × time_increment
TF 位姿    → 第 i 束激光采集时刻的雷达位姿
```

运动畸变校正需要依靠这种 **下标—采集时间—机器人位姿** 的一一对应关系，因此这里必须按原有 `i = 0, 1, 2, ...` 的顺序保存数据。

## 7. 查询第一束激光时刻的雷达位姿

```cpp
tf::Stamped<tf::Pose> frame_base_pose;
if (!getLaserPose(frame_base_pose, startTime, tf_))
{
    ROS_WARN("Not Start Pose, Can not calibrate");
    return;
}
```

`getLaserPose()` 会查询 `startTime` 时刻的 TF：

```text
odom → base_laser
```

即得到：**第一束激光采集时，激光雷达在 `odom` 坐标系中的位置和姿态。**

这个位姿具有两个作用：

1. 作为整帧扫描运动补偿的基准时刻；
2. 将处理后的激光点发布到 `odom` 坐标系。

如果 TF 缓冲区没有该时刻的变换，或者 TF 树不连通，便无法判断雷达当时的位置，因此该帧数据直接丢弃。

### `getLaserPose()` 的主要逻辑

```cpp
robot_pose.frame_id_ = "base_laser";
robot_pose.stamp_ = dt;

tf_->waitForTransform("/odom", "/base_laser", dt, ros::Duration(0.5));
tf_->transformPose("/odom", robot_pose, odom_pose);
```

它创建一个位于 `base_laser` 原点的位姿，再将该位姿变换到 `odom` 坐标系。输出的 `odom_pose` 即为给定时刻雷达在 `odom` 中的位姿。

## 8. 保存原始数据，并执行运动畸变校正

```cpp
const std::vector<double> raw_ranges = ranges;
const std::vector<double> raw_angles = angles;

Lidar_Calibration(ranges,
                  angles,
                  startTime,
                  endTime,
                  tf_);
```

`Lidar_Calibration()` 接收的是非常量引用：

```cpp
std::vector<double>& ranges,
std::vector<double>& angles
```

因此它可以直接修改 `ranges` 与 `angles`，将原始扫描改为补偿后的扫描。

所以在调用前复制两份数据：

- `raw_ranges`、`raw_angles`：保留未校正的原始扫描；
- `ranges`、`angles`：用于存放校正后的扫描结果。

这样 RViz 可以同时显示两种点云，直观看到运动畸变校正的效果。

## 9. 为什么一帧激光会产生运动畸变？

二维激光雷达不是在一个瞬间采完一整圈，而是逐束依次采样。

假设一帧扫描持续 `0.1 s`：

```text
第 0 束                  第 359 束                   第 719 束
 t = 0                    t = 0.05 s                  t = 0.1 s
   │                          │                           │
   ▼                          ▼                           ▼
雷达位姿 A                 雷达位姿 B                  雷达位姿 C
```

如果机器人在扫描期间前进或旋转，不同方向的点便是在不同雷达位姿下测得的。

例如，机器人旋转时扫描一面真实的直墙：

```text
真实墙面：                 不补偿时的点云：

│                          )
│                         )
│                        )
│                       )
```

这就是运动畸变。它会导致：

- 墙面弯曲；
- 障碍物边缘重影；
- 连续两帧点云难以重合；
- ICP、定位、建图等算法精度下降。

运动补偿的核心目标是：**根据每束激光实际采样时的雷达位姿，将所有点统一表达在同一个参考时刻的坐标系中。**

本程序选择的参考时刻是整帧第一束激光的 `startTime`。

## 10. `Lidar_Calibration()` 的分段校正思路

`Lidar_Calibration()` 位于源文件第 250 行，其流程如下：

1. 统计整帧激光束数量；
2. 将扫描时间按 `5 ms` 划分成小段；
3. 查询每一段起点和终点时刻的雷达位姿；
4. 假设机器人在该小段内做匀速运动；
5. 对段内每束激光插值得到对应时刻的位姿；
6. 调用 `Lidar_MotionCalibration()`，将这一小段的点补偿到整帧第一束激光的参考位姿。

处理结构如下：

```text
一帧扫描
   │
   ├── 第 1 段：0 ~ 5 ms
   ├── 第 2 段：5 ~ 10 ms
   ├── 第 3 段：10 ~ 15 ms
   └── ...
          │
          ▼
段首 TF + 段尾 TF
          │
          ▼
假设段内匀速，插值得到每束激光的位姿
          │
          ▼
将每束激光补偿到整帧起始时刻
```

分段越短，匀速运动假设通常越接近真实轨迹；但 TF 查询和计算次数也会增加。这里使用 `5 ms` 作为分段时长。

## 11. 完成 `Lidar_MotionCalibration()` TODO

> 以下代码是**写进作业 TODO 的完整参考实现**。本文档只提供可手抄的答案，尚未替你修改 `LidarMotionUndistortion.cpp`。
>
> 它的目标不是直接修改距离，而是先把每束激光点变到统一的参考坐标系，再转换回距离和角度。统一参考系是**整帧第一束激光采集时的 `base_laser` 坐标系**。

### 11.1 先记住最重要的一条公式

设：

- $T_{odom\leftarrow laser}(t_j)$：第 $j$ 束激光采集时，`base_laser` 到 `odom` 的位姿变换；
- $T_{odom\leftarrow laser}(t_0)$：整帧第一束激光采集时的位姿，也就是 `frame_base_pose`；
- $p_{laser,j}$：第 $j$ 束激光点在它自己的瞬时雷达坐标系中的坐标；
- $p_{base,j}$：校正后、统一表示在整帧起始雷达坐标系中的坐标。

则运动补偿是：

$$
p_{base,j} =
T_{odom\leftarrow laser}(t_0)^{-1}
\cdot T_{odom\leftarrow laser}(t_j)
\cdot p_{laser,j}
$$

可以按三个动作理解：

```text
第 j 束点（瞬时 base_laser）
        │  T_j
        ▼
      odom 坐标系
        │  inverse(T_base)
        ▼
整帧第一束对应的 base_laser 坐标系
```

后面的 `PublishCloudInOdom()` 会再用第一束激光的位姿 `T_base` 把这些点发布到 `odom`。因此这里**必须先乘 `inverse(T_base)`**，否则会重复施加机器人位姿变换。

### 11.2 可直接手抄的完整代码

用下面的函数体替换源文件中 `Lidar_MotionCalibration()` 的 `// TODO` 部分。函数签名保持不变。

```cpp
void Lidar_MotionCalibration(
        tf::Stamped<tf::Pose> frame_base_pose,
        tf::Stamped<tf::Pose> frame_start_pose,
        tf::Stamped<tf::Pose> frame_end_pose,
        std::vector<double>& ranges,
        std::vector<double>& angles,
        int startIndex,
        int& beam_number)
{
    // 1. 先确认本段的数组范围合法。
    //    startIndex + beam_number 直接以 int 相加可能溢出，
    //    所以先检查正负，再转换为 size_t。
    if (beam_number <= 0 || startIndex < 0 ||
        ranges.size() != angles.size())
    {
        ROS_WARN("Invalid laser calibration segment");
        return;
    }

    const std::size_t first = static_cast<std::size_t>(startIndex);
    const std::size_t count = static_cast<std::size_t>(beam_number);
    if (first > ranges.size() || count > ranges.size() - first)
    {
        ROS_WARN("Laser calibration segment is out of bounds");
        return;
    }

    // 2. frame_base_pose 是整帧第一束的 T_odom_laser(t0)。
    //    它是整个扫描帧的统一参考，不能随分段改变。
    const tf::Transform base_transform(frame_base_pose.getRotation(),
                                       frame_base_pose.getOrigin());
    const tf::Transform base_inverse = base_transform.inverse();

    // 3. 当前 5 ms 分段的首尾位置与姿态。
    //    后续使用它们插值得到每一束激光采集瞬间的位姿。
    const tf::Vector3 start_origin = frame_start_pose.getOrigin();
    const tf::Vector3 end_origin = frame_end_pose.getOrigin();
    const tf::Quaternion start_rotation = frame_start_pose.getRotation();
    const tf::Quaternion end_rotation = frame_end_pose.getRotation();

    // 4. 逐束校正当前分段的激光数据。
    for (std::size_t j = 0; j < count; ++j)
    {
        const std::size_t index = first + j;
        const double range = ranges[index];
        const double angle = angles[index];

        // 与发布点云时的约定相同：无效点不参与计算，置零后跳过。
        if (range < 0.05 || !std::isfinite(range) || !std::isfinite(angle))
        {
            ranges[index] = 0.0;
            angles[index] = 0.0;
            continue;
        }

        // 5. 计算第 j 束在本段内的时间比例 alpha。
        //    j == 0 时 alpha = 0，恰好使用段首位姿；
        //    j == count - 1 时 alpha = 1，恰好使用段尾位姿。
        //    若该段只有一束激光，规定它使用段首位姿，避免除零。
        const double alpha = (count == 1)
            ? 0.0
            : static_cast<double>(j) / static_cast<double>(count - 1);

        // 6. 假设短时间段内机器人匀速运动：
        //    - 平移使用线性插值 lerp；
        //    - 旋转使用四元数球面插值 slerp。
        // slerp 能正确处理航向角在 +pi 和 -pi 附近跳变的问题。
        const tf::Vector3 interpolated_origin =
            start_origin.lerp(end_origin, alpha);
        const tf::Quaternion interpolated_rotation =
            start_rotation.slerp(end_rotation, alpha);
        const tf::Transform beam_transform(interpolated_rotation,
                                           interpolated_origin);

        // 7. 先把本束激光的极坐标 (range, angle) 转成直角坐标。
        //    point_in_laser 表示“第 j 束被采到那一刻”的雷达坐标系中的点。
        const tf::Vector3 point_in_laser(
            range * std::cos(angle),
            range * std::sin(angle),
            0.0);

        // 8. 完成运动补偿：
        //    瞬时雷达系 --beam_transform--> odom
        //    odom --base_inverse--> 整帧第一束的雷达系
        const tf::Vector3 point_in_base =
            base_inverse * (beam_transform * point_in_laser);

        // 防止异常 TF 或数值计算把非法值写回扫描数组。
        if (!std::isfinite(point_in_base.x()) ||
            !std::isfinite(point_in_base.y()))
        {
            ranges[index] = 0.0;
            angles[index] = 0.0;
            continue;
        }

        // 9. 接口仍以二维极坐标保存结果，因此把补偿后的直角坐标转回去。
        const double corrected_range = std::hypot(point_in_base.x(),
                                                  point_in_base.y());
        const double corrected_angle = std::atan2(point_in_base.y(),
                                                  point_in_base.x());

        // hypot 和 atan2 在正常有限输入下应产生有限值；这里仍做防御检查。
        if (!std::isfinite(corrected_range) ||
            !std::isfinite(corrected_angle))
        {
            ranges[index] = 0.0;
            angles[index] = 0.0;
            continue;
        }

        // 10. 原地写回：后续 PublishCloudInOdom() 会将它们当作
        //     “整帧起始 base_laser 坐标系”中的极坐标点来发布。
        ranges[index] = corrected_range;
        angles[index] = corrected_angle;
    }
}
```

### 11.3 按照数据流理解每一部分

| 步骤 | 代码关键字 | 它解决的问题 |
|---|---|---|
| 1 | `first`、`count`、越界检查 | 当前 5 ms 分段不能访问到其他分段的数据或数组外的数据。 |
| 2 | `base_transform.inverse()` | 将世界/`odom` 中的点转换回整帧第一束激光的坐标系。 |
| 3 | `start_origin`、`end_origin` | 得到当前分段首尾时刻的机器人位置。 |
| 4 | `for (j ...)` | 分段内每束激光都有不同的采样时刻，必须逐束处理。 |
| 5 | `alpha` | 用 $0\sim1$ 表示该束激光位于分段开始和结束之间的相对时间。 |
| 6 | `lerp`、`slerp` | 估算这束激光真正采集时的雷达位姿。 |
| 7 | `cos`、`sin` | 将传感器输出的距离/角度转换为二维坐标点。 |
| 8 | `base_inverse * (beam_transform * point)` | 核心去畸变：瞬时雷达系 → `odom` → 起始雷达系。 |
| 9 | `hypot`、`atan2` | 将补偿后的 $(x,y)$ 再保存回 `ranges`、`angles` 接口。 |

### 11.4 必须手算验证的四个情况

在手抄前和调试后，可以用以下情况检查公式方向是否写反：

1. **本段第一束**：`j == 0`，因此 `alpha == 0`，插值位姿必须等于 `frame_start_pose`。
2. **本段最后一束**：`j == count - 1`，因此 `alpha == 1`，插值位姿必须等于 `frame_end_pose`。
3. **机器人静止**：所有时刻的 $T_j$ 都等于 $T_{base}$，因此

   $$
   T_{base}^{-1} \cdot T_j \cdot p = p
   $$

   校正前后的距离和角度应基本不变。
4. **整帧第一束**：其瞬时位姿就是 `frame_base_pose`，同样满足

   $$
   T_{base}^{-1} \cdot T_{base} \cdot p = p
   $$

   第一束不应被额外平移或旋转。

### 11.5 两个容易写错的地方

- **不要只改 `range`**：机器人旋转后，点的方向也改变，因此必须先转换为 $(x,y)$，做刚体变换后再用 `atan2()` 得到新角度。
- **不要将每段的 `frame_start_pose` 当作基准**：它只用于段内插值；所有分段都必须回到同一个 `frame_base_pose`，否则不同分段的点仍然在不同坐标系中。

### 11.6 现有调用代码的一个边界提醒

`Lidar_Calibration()` 目前是 `void`。如果前面几个分段已经原地校正、后面的 TF 查询失败，函数会直接返回，而回调仍可能发布这份“部分校正”的 `ranges` / `angles`。

这不影响上面 TODO 的坐标变换公式，但在进一步完善工程时，更稳妥的设计是让 `Lidar_Calibration()` 返回 `bool`：只有所有分段校正成功时，才发布 `corrected_cloud`。当前手抄作业先保持既有函数签名和调用方式即可。

## 12. 从极坐标到 `odom` 点云：`PublishCloudInOdom()`

`PublishCloudInOdom()` 位于源文件第 118 行。它把每束激光表示的极坐标点转成 `odom` 坐标系中的 PCL 点云。

### 12.1 激光极坐标转雷达坐标系直角坐标

对第 `i` 束激光：

- 距离：$r$；
- 角度：$\theta$。

在激光雷达自身坐标系中：

$$
x_l = r\cos(\theta)
$$

$$
y_l = r\sin(\theta)
$$

对应代码：

```cpp
const double laser_x = ranges[i] * std::cos(angles[i]);
const double laser_y = ranges[i] * std::sin(angles[i]);
```

### 12.2 雷达坐标系转 `odom` 坐标系

从 TF 中提取第一束激光时刻的雷达位姿：

```text
平移：origin_x, origin_y
偏航角：yaw
```

二维刚体变换为：

$$
\begin{bmatrix}
x_o \\
y_o
\end{bmatrix}
=
\begin{bmatrix}
\cos(\mathrm{yaw}) & -\sin(\mathrm{yaw}) \\
\sin(\mathrm{yaw}) & \cos(\mathrm{yaw})
\end{bmatrix}
\begin{bmatrix}
x_l \\
y_l
\end{bmatrix}
+
\begin{bmatrix}
origin_x \\
origin_y
\end{bmatrix}
$$

对应代码：

```cpp
const double odom_x = laser_x * cos_yaw - laser_y * sin_yaw + origin_x;
const double odom_y = laser_x * sin_yaw + laser_y * cos_yaw + origin_y;
```

由于这是二维激光雷达，所有点都位于扫描平面，所以：

```cpp
point.z = 0.0F;
```

## 14. 总结

`ScanCallBack()` 的职责可以概括为：

```text
接收一帧按时间顺序采样的激光束
        │
        ▼
清洗无效 ranges / angles
        │
        ▼
依据每束激光的采样时刻查询机器人运动位姿
        │
        ▼
将不同时间采到的点统一补偿到第一束激光的参考时刻
        │
        ▼
转换为 odom 坐标系下的点云并发布到 RViz
```

其中，去畸变效果是否真正生效，取决于 `Lidar_MotionCalibration()` 是否完成。当前函数尚未实现，因此当前的“校正后点云”与原始点云仍然相同。
