# 二、A*：把"终点在哪"这个信息用上

## 2.1 Dijkstra 浪费在哪

回看上一篇最后那张图：21×11 空地图，从 `(1,5)` 走到 `(19,5)`，Dijkstra 在 231 格里
**扩展了 202 格**，就为了一条 18 格的直线。

浪费的本质是：Dijkstra 按 `g` 排序，也就是"离**起点**多远"。
所有 `g` 相近的格子在它眼里一样重要 —— 不管是朝着终点的那一格，还是背朝终点的那一格。

它必须这样，因为**它压根不知道终点在哪儿**。终点只在"出堆时判断一下是不是它"这一处被用到，
其余全程都没参与决策。

A* 干的事就一句话：**把终点的位置提前用起来**。

## 2.2 g、h、f 三个字母

| 符号 | 全名 | 含义 | 性质 |
|---|---|---|---|
| `g(n)` | cost so far | 从起点到 `n` 的**已知**代价 | 是**事实**，走过才知道，会被改小 |
| `h(n)` | heuristic | 从 `n` 到终点的代价**估计** | 是**猜测**，不需要搜索就能算，永不改变 |
| `f(n)` | `g + h` | 经过 `n` 的整条路的**总代价估计** | 排序键 |

再引入一个只在证明里出现、程序永远算不出来的量：

- `h*(n)`：从 `n` 到终点的**真实**最短代价。
- `C*`：起点到终点的真实最短代价（也就是 `h*(start)`）。

`h` 是对 `h*` 的估计。整个 A* 理论就是在讨论"这个估计得满足什么条件，结论才成立"。

代码里三者分别是 `AStar::Node` 的 `g` / `h` / `f`，四种 `h` 的算式在 `rawHeuristic()`。

## 2.3 排序键为什么是 `g + h`，而不是 `h`

这是 A* 最核心的设计选择。三种排序键，三种算法：

| 排序键 | 名字 | 行为 | 最优? |
|---|---|---|---|
| `g` | **Dijkstra** | 只看"来路"。以起点为圆心均匀铺开，方向盲 | ✅ |
| `h` | **贪心最优先**（greedy best-first） | 只看"去路"。一头朝终点冲，非常快 | ❌ |
| `g + h` | **A\*** | 两边都看 | ✅（h 可采纳时） |

贪心最优先为什么不最优？因为它完全无视已经花掉的代价。
它会一头扎进一个朝向终点的死胡同，绕出来之后，仍然只按"当前离终点多近"选下一步 ——
一条明显更绕的路只要"看起来离终点更近"，它就会走。

`f = g + h` 的含义是：**"如果最终路线经过 `n`，全程大概要花多少"**。
按这个值排序，就是"永远先去检查目前看起来最有希望的那条完整路线"。
这既尊重了已经付出的代价（`g`），又利用了对未来的判断（`h`）。

两个极端情形自动落回熟悉的算法：

- `h ≡ 0` → `f = g` → **就是 Dijkstra**（本包 `--h zero`）；
- `h = h*`（估计完全准确）→ A* 一步不多走，直接沿最优路走到终点。

所以 **A* 是一族算法**，`h` 的质量决定它落在"Dijkstra"和"直达"之间的哪个位置。

## 2.4 可采纳（admissible）：最优性的条件

> **定义**：`h` 可采纳 ⟺ 对所有 `n`，`h(n) ≤ h*(n)`。
>
> 白话：**只许低估，不许高估**。

为什么低估是安全的？因为 A* 是靠"`f` 小的先出堆"来做决策的。
`h` 低估 ⇒ `f` 低估 ⇒ 一条真正的最优路"看起来更便宜"⇒ 它会被优先检查。
反过来 `h` 高估 ⇒ 最优路"看起来很贵"⇒ 可能一直排在后面，等 A* 先撞上终点、返回一条次优路。

### 本包四种 h 的可采纳性

设 `dx = |x_n - x_goal|`，`dy = |y_n - y_goal|`。

| h | 算式 | 4 邻域 | 8 邻域 |
|---|---|---|---|
| `zero` | `0` | ✅ 可采纳（也最弱） | ✅ |
| `manhattan` | `dx + dy` | ✅ **恰好等于 h\*** | ❌ **高估** |
| `euclidean` | `√(dx²+dy²)` | ✅ 可采纳但偏弱 | ✅ 可采纳但偏弱 |
| `diagonal` (octile) | `√2·min(dx,dy) + \|dx−dy\|` | ❌ 高估 | ✅ **恰好等于 h\*** |

关键那一格：**8 邻域下曼哈顿距离高估**。斜走一步真实代价 `√2 ≈ 1.414`，
曼哈顿把它算成 `2`。差了 41%，路径就不再保证最短。

octile 那个式子的来历很直观：斜着走能同时消掉一格 `dx` 和一格 `dy`，
所以尽量斜走 `min(dx,dy)` 步（每步 `√2`），剩下的 `|dx−dy|` 只能直走（每步 `1`）。
空地上这就是精确答案。

代码里 `isHeuristicAdmissible()` 按邻域把这张表编码进去了，
`admissibilityWarning()` 负责在你选错时开口提醒。

### 为什么"恰好等于 h*"是最好的选择

`h ≤ h*` 是**约束**，在满足约束的前提下 `h` **越大越好** —— 越接近 `h*`，
`f` 越准，被误导去检查的无用节点就越少。

`zero` 和 `h*` 是两个端点：`zero` 满足约束但毫无信息量（退化成 Dijkstra）；
`h*` 把约束用到了极限。所以 4 邻域选 manhattan、8 邻域选 octile ——
它们在各自的邻域下**就是** `h*`（对空地而言），不能再好了。

euclidean 在 8 邻域下始终 ≤ octile（因为直线距离 ≤ 沿格子走的距离），
所以它是个"合法但偷懒"的估计，实测扩展数介于 zero 和 octile 之间。

## 2.5 A* 最优性证明

> **定理**：若 `h` 可采纳，则 A* 返回的路径代价等于 `C*`。

**证明**（反证）。假设终点 `t` 出堆时 `g[t] > C*`。

考察某条真实最优路 `P: s → … → t`（代价 `C*`）。
`t` 出堆的那一刻，`P` 上必然存在**至少一个还在 OPEN 里的点**。理由：
`s` 已经出过堆（它是第一个），`t` 正在出堆但还没算进 CLOSED；沿着 `P` 走，
必有第一个尚未出堆的点 —— 记作 `z`。`z` 的前驱在 CLOSED 里，
而节点进 CLOSED 时会松弛所有邻居，所以 `z` 确实在 OPEN 里。

由于 `P` 的前缀也是到 `z` 的最优路，且 `z` 的所有前驱都已 CLOSED（`g` 已最优），
松弛保证 `g[z] = g*(z)`（`z` 的真实最短代价）。于是

```
f(z) = g[z] + h(z)
     = g*(z) + h(z)
     ≤ g*(z) + h*(z)        <- 可采纳性，唯一用到它的一步
     = C*                   <- z 在最优路上，两段之和就是 C*
     < g[t] = f(t)          <- 假设（注意 h(t)=0）
```

得到 `f(z) < f(t)`，而 `z` 在 OPEN 里 —— 那么这一轮出堆的应该是 `z` 而不是 `t`，矛盾。∎

**这个证明是整个 A* 的地基**，值得看第二遍。注意它在哪里用了什么：

- `h(t) = 0`：终点的估计必须为 0，否则 `f(t) ≠ g[t]`，最后一步的比较就断了。四种 h 都满足。
- **可采纳性只用了一次**，就是 `h(z) ≤ h*(z)` 那一行。
- 顺带解释了 4.1 那个坑：证明成立的前提是"`t` **出堆**"。
  如果在 `t` 刚**入堆**时就返回，`g[t]` 只是某条路的代价，上面的论证一句也用不上。

## 2.6 一致（consistent）：比可采纳更强的条件

> **定义**：`h` 一致（也叫单调 monotone）⟺ 对每条边 `(n, n')`，
> `h(n) ≤ c(n,n') + h(n')`。

这就是三角不等式：从 `n` 出发的估计，不能比"先走到 `n'` 再估计"更贵。

两个关键事实：

1. **一致 + `h(goal)=0` ⇒ 可采纳**（沿最优路把不等式一路相加即得），反之不成立。
   所以一致是**更强**的条件。
2. **一致 ⟺ `f` 沿任何路径单调不减**。因为
   `f(n') = g[n'] + h(n') = g[n] + c + h(n') ≥ g[n] + h(n) = f(n)`。
   于是出堆的 `f` 序列单调不减 —— 这正好是上一篇 Dijkstra 那个"`g` 单调不减"结论的推广。

### 为什么这件事很重要：CLOSED 能不能永不回头

伪代码第 7 行"`nb` 已在 CLOSED 就直接跳过"，严格来说需要的是**一致性**，不是可采纳性。

- `h` 一致 ⇒ 节点出堆时 `g` 一定已最优 ⇒ 永不需要重开（reopen），跳过是安全的。
- `h` 仅可采纳但不一致 ⇒ 一个节点可能出堆之后才发现更短的路。
  教科书版 A* 这时要把它从 CLOSED 拿回 OPEN（reopen），否则**丢掉最优性**。

本包和几乎所有工程实现一样，**不做 reopen**。这在实践中没问题，因为：

| h | 一致? | 理由 |
|---|---|---|
| `zero` | ✅ | `0 ≤ c + 0`，因为 `c ≥ 0`（这就是 Dijkstra 那个非负边权条件） |
| `euclidean` | ✅ | 三角不等式：两点直线距离之差 ≤ 两点间距 = 边代价 |
| `diagonal` (octile) | ✅ | octile 是格子上的度量，同样满足三角不等式 |
| `manhattan` @ 8 邻域 | ❌ | 斜走一步 `h` 变化 **2**，边代价只有 `√2` —— `2 > 1.414`，不等式破了 |

注意最后一行：**8 邻域下的曼哈顿距离同时破坏了可采纳性和一致性**。
这不是两个独立的毛病，而是同一件事（高估）的两种表述。它也解释了为什么这个配置
在实测中真的会给出更长的路径 —— 见 [03-compare.md](03-compare.md)。

而 `weight > 1` 的 Weighted A*（`f = g + w·h`）则破坏一致性但不完全失控，
它的代价有明确上界，见 2.8。

## 2.7 h 精确时，f 沿最优路是常数

这是个能立刻上手验证、而且极能加深理解的观察。

若 `h = h*`，则最优路上每个点 `n` 都有 `g(n) + h*(n) = C*` —— `f` 是个**常数**。
直观解释：`g` 每涨一点，`h` 就恰好落一样多，因为"已走"和"还剩"加起来就是全程。

4 邻域 + 曼哈顿正好是这种情形。跑一遍：

```bash
rosrun astar_tutorial astar_console_demo \
    --map empty --size 5 3 --conn 4 --h manhattan --start 0 1 --goal 4 1 --step --no-skips
```

5 格宽的空地图，从最左走到最右。实测结果：

```
共 5 步，每一步出堆节点的 f 都是 4.000
路径代价 4.0000
```

**5 步**（对比同一张图 Dijkstra 的 **12 步**、扩展 12/15 格）。而且 5 步里
每一步的 `f` 都是 `4.000` —— A* 一格也没走错，因为 `h` 完美，它从第一步就知道答案是 4。

反过来，这也是个实用的调试手段：**如果你的 h 号称精确，而 `f` 在最优路上有波动，
那 `h` 或边代价一定有 bug**。

顺带一提，`f` 沿最优路恒定还解释了为什么 A* 在空地上会出现大量 `f` 相同的节点 ——
平局非常多，谁先出堆全看堆的实现细节。这就是"tie-breaking"话题的由来（2.9）。

## 2.8 Weighted A*：明码标价地买速度

把排序键改成

```
f = g + w · h        (w ≥ 1)
```

`w > 1` 时 `w·h` 可能高估，**最优性没了**。但换来的不是无底洞：

> **定理**：Weighted A* 返回的路径代价 `≤ w · C*`。

直觉：`w·h` 至多把真实剩余代价放大 `w` 倍，所以被误导的程度也被 `w` 倍框住。
（严格证明和 2.5 同构：把 `h(z) ≤ h*(z)` 换成 `w·h(z) ≤ w·h*(z)`，
最后得到 `f(t) ≤ w·C*`。）

这是**有界次优**（bounded suboptimality），是工程上最有用的一类保证：
`w = 1.5` 就是"我接受最多长 50% 的路，换更快的搜索"。

实测（60×40 带墙地图，见 `../README.md` 第 5 节）：

| w | 扩展数 | 代价 | 相对最优 |
|---|---|---|---|
| 1.0 | 1542 | 105.15 | 1.000 |
| 1.5 | 1473 | 107.15 | 1.019 |
| 3.0 | **718** | 110.57 | 1.051 |

`w = 3` 扩展数少了一半多，路径只长了 5.1% —— 远好于理论上界 3 倍。
**上界是最坏情况保证，不是典型表现**，这一点在工程上非常常见。

（实际用的时候一般还会配上 ARA*：先用大 `w` 快速拿一条可行路，
再逐步调小 `w` 迭代改进，随时可以中断取当前最好解。）

## 2.9 平局怎么破（tie-breaking）

空地图上大量节点 `f` 完全相同，A* 只能任选一个 —— 于是它会把整片"等 `f` 区域"
都填掉，虽然其中大部分对结果毫无贡献。

常见小技巧：把 `h` 乘上 `1 + ε`（本包的 `tie_breaker`，试 `1.0001`）。
效果是 `f` 相同时优先展开 `h` 更小的（也就是离终点更近的）那个，
搜索形状从"胖椭圆"收成"细走廊"。

严格说这让 `h` 不再可采纳（代码会照实警告），但 `ε` 极小，
实测代价和最优解一模一样。这里要分清两件事：

> **可采纳性是最优的充分条件，不是必要条件。**
> 放弃它 = 放弃**保证**，不等于必然变差。这一次亏没亏，要看运气。

要不要接受"通常没事"，是工程判断，不是数学结论。教学场景我建议保持 `1.0`，
先把有保证的版本看明白。

## 2.10 复杂度和内存

时间复杂度和 Dijkstra 同阶：`O((V+E) log V)`，`V` 是**实际扩展的**节点数。
`h` 的作用不是改善阶，而是**大幅压小那个 `V`**（实测 202 → 19）。

内存是 A* 真正的软肋：OPEN 和 CLOSED 都要显式存着。
本包用一个 `std::vector<Node>` 平铺整张地图（`nodes_`），所以内存是 `O(格子数)`，
和搜索规模无关 —— 教学地图这样最简单直接。真做大地图要换 hash 表按需分配。

内存受限时的成熟方案是 IDA*（迭代加深，`O(深度)` 内存）和 SMA*，
但栅格规划里更常见的是换个思路：JPS（跳点，只扩展"跳点"）、
分层规划（先粗后细），或者干脆换到采样法（RRT / RRT*）。
