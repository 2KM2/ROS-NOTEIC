# 里程计标定作业运行与调试指南

> 工程目录（宿主机）：`/home/zachary/workspace/ROS_NOETIC`<br>
> 工作空间（容器内）：`/workspace/src/odom_ws`<br>
> ROS 版本：Noetic<br>
> 节点包：`calib_odom`

本文件说明如何在 Docker ROS Noetic 环境中，构建、测试、运行、回放数据包并通过 RViz 验证里程计标定作业。

---

## 1. 本作业的运行目标

节点运行后会处理：

```text
/sick_scan 激光数据
        +
TF: odom -> base_link
```

并发布三条用于比较的轨迹：

| 话题 | 含义 |
|---|---|
| `/odom_path_pub_` | 原始里程计相对增量积分得到的路径 |
| `/scan_path_pub_` | PI-ICP 激光扫描匹配相对增量积分得到的路径 |
| `/calib_path_pub_` | 使用最小二乘校正矩阵后重新积分得到的路径 |

整体流程：

```text
/sick_scan + TF(odom -> base_link)
                  │
                  ▼
        cal_delta_distance()
                  │
                  ├──> odom_increment
                  │          │
                  ▼          ▼
PI-ICP 扫描匹配 ───────> Add_Data()
                              │
                              ▼
                         A x ≈ b
                              │
                              ▼
                           Solve()
                              │
                              ▼
                   correct_matrix × odom_increment
                              │
                              ▼
                     /calib_path_pub_
```

## 3. 第一步：构建并运行自动测试

这一步不需要 RViz、不需要 `roscore`，用于先验证 `Add_Data()` 和 `Solve()` 的核心数学实现。

进入容器：

```bash
docker exec -it ros_noetic_hw bash
```

在容器内执行：

```bash
cd /workspace/src/odom_ws
source /opt/ros/noetic/setup.bash

# 编译作业节点和测试目标
catkin build calib_odom

# 加载本工作空间
source devel/setup.bash

# 运行 GoogleTest
catkin test calib_odom --no-status --summarize

# 汇总测试结果
catkin_test_results build
```

预期结果：

```text
[Successful] calib_odom

4 个 GoogleTest 测试全部通过
Summary: 8 tests, 0 errors, 0 failures, 0 skipped
```

测试覆盖：

```text
1. Add_Data() + Solve() 可以恢复一个已知的 3×3 校正矩阵；
2. 达到样本容量后拒绝继续写入，避免矩阵越界；
3. 当观测矩阵 rank(A) < 9 时拒绝不可靠求解；
4. 清空数据后，样本计数同步归零，可以重新采集。
```

## 4. 第二步：确认没有遗留的 ROS 节点

为避免新旧标定节点、旧的 bag 回放或旧的 `roscore` 相互干扰，运行前检查：

```bash
source /opt/ros/noetic/setup.bash
rosnode list
```

在完全空闲的 ROS master 中，通常只会看到：

```text
/rosout
```

若发现之前启动的标定节点，例如：

```text
/message_filter_node
```

说明它仍在运行。应在启动新节点前结束旧终端中的 `roslaunch`，或确认该节点不再需要后执行：

```bash
rosnode kill /message_filter_node
```

> `roslaunch calib_odom odomCalib.launch` 在没有 ROS master 时会自动启动 `roscore`，一般不需要手动运行 `roscore`。

```text
终端 1：启动标定节点
终端 2：播放 odom.bag
终端 3：启动 RViz 并在最后触发标定
```

### 5.1 终端 1：启动标定节点

宿主机执行：

```bash
docker exec -it ros_noetic_hw bash
```

容器内执行：

```bash
cd /workspace/src/odom_ws
source /opt/ros/noetic/setup.bash

```

初始预期输出：

```text

```

启动文件中的：


表示节点使用 bag 发布的仿真时间，因此回放时**必须**使用：

```text
Data Cnt:1
Data Cnt:2
Data Cnt:3
...
```

`Data Cnt` 表示已成功写入最小二乘方程 `Ax≈b` 的有效激光/里程计帧对数量。

```text

```

建议直接使用：

```bash
cd /home/zachary/workspace/ROS_NOETIC/docker

```

这个配置会自动设置 `Fixed Frame=odom`，并添加：

## 6. RViz 的配置方法

### 6.1 设置固定坐标系

在 RViz 左侧：

```text
Global Options
└── Fixed Frame
```

设为：

```text
odom
```

原因：三条作业路径的 `header.frame_id` 都是：

```text
odom
```

### 6.2 添加三条 Path

依次点击：

```text
Add
└── By topic
```

添加：

```text
/odom_path_pub_
/scan_path_pub_
/calib_path_pub_
```

建议使用不同颜色：

| 话题 | 建议颜色 | 含义 |
|---|---|---|
| `/odom_path_pub_` | 红色 | 原始里程计路径 |
| `/scan_path_pub_` | 绿色 | 激光 PI-ICP 路径 |
| `/calib_path_pub_` | 蓝色 | 最小二乘校正后的路径 |

在未触发标定前，只会有：

```text
红色：/odom_path_pub_
绿色：/scan_path_pub_
```

标定完成后才会出现：

```text
蓝色：/calib_path_pub_
```

## 7. 第四步：触发最小二乘标定

在终端 1 已经持续打印 `Data Cnt`，并且 bag 回放结束或已积累足够样本后，打开一个新终端：

```bash
docker exec -it ros_noetic_hw bash
```

容器内执行：

```bash
source /opt/ros/noetic/setup.bash
source /workspace/src/odom_ws/devel/setup.bash

rostopic pub -1 /calib_flag std_msgs/Empty "{}"
```

参数含义：

```text
-1：只发布一次消息后退出。
/calib_flag：标定触发话题。
std_msgs/Empty：不需要负载内容的消息类型。
{}：空消息内容。
```

标定节点预期输出：

```text
correct_matrix:
[ ... ... ... ]
[ ... ... ... ]
[ ... ... ... ]

calibration over!!!!
```

此时节点会：

```text
1. 解最小二乘问题 min ||Ax-b||²；
2. 得到 correct_matrix；
3. 用该矩阵校正已保存的 odom_increment；
4. 积分生成 /calib_path_pub_；
5. 停止订阅后续激光数据。
```

## 8. 怎样判断验证成功

### 8.1 构建和测试层面

以下都应当成功：

```text
catkin build calib_odom
catkin test calib_odom
catkin_test_results build
```

预期：

```text
0 errors, 0 failures
```

### 8.2 节点运行层面

检查：

```text
终端打印 Calibration Online,Wait for Data!!!!!!!
Data Cnt 持续增加
没有持续出现 PI ICP Failed!!!!!!!
发布 /calib_flag 后输出 correct_matrix
输出 calibration over!!!!
```

### 8.3 ROS 话题层面

查看路径话题：

```bash
source /opt/ros/noetic/setup.bash
rostopic list | grep path
```

应看到：

```text
/calib_path_pub_
/odom_path_pub_
/scan_path_pub_
```

查看校正路径是否真的有消息：

```bash
rostopic echo -n 1 /calib_path_pub_
```

预期消息类型为：

```text
nav_msgs/Path
```

且 `poses` 中应当包含多个路径点。

### 8.4 RViz 效果层面

最终比较：

```text
红色：odom_path_pub_   （校正前）
绿色：scan_path_pub_   （激光匹配参考）
蓝色：calib_path_pub_  （校正后）
```

预期现象是：

```text
蓝色 calib_path 相比红色 odom_path，应整体更接近绿色 scan_path。
```

注意：并非每一个路径点都必须完全重合。激光匹配和线性校正模型本身都存在噪声与近似；判断重点是总体偏差是否减小。

## 10. 常见问题与排查

### 10.1 `catkin build` 失败

先确认环境：

```bash
source /opt/ros/noetic/setup.bash
cd /workspace/src/odom_ws
catkin build calib_odom
```

若提示构建空间由其他工具创建，例如：

```text
build space was previously built by colcon
```

只删除可再生的构建产物后再构建：

```bash
cd /workspace/src/odom_ws
rm -rf build devel install logs
catkin build calib_odom
```

> 不要删除 `src/`，其中包含作业源码、文档和本地 bag 数据。

---

### 10.2 节点没有打印 `Data Cnt`

按顺序检查：

```bash
source /opt/ros/noetic/setup.bash

# 1. bag 是否在发布激光
rostopic echo -n 1 /sick_scan

# 2. 能否在当前时间查询 TF
rosrun tf tf_echo odom base_link

# 3. 查看当前可用话题
rostopic list
```

需要确认：

```text
rosbag play --clock ... 正在运行；
/sick_scan 有数据；
TF 中存在 odom -> base_link；
标定节点已 source devel/setup.bash 后启动；
机器人单帧增量超过程序设定的小运动阈值。
```

程序的运动阈值为：

```text
前进/左移绝对值 < 0.05 m
且
偏航角绝对值 < 5°
```

当三项同时满足时，本帧不作为标定样本，但程序仍会推进参考帧，保证下一帧里程计和激光数据配对正确。

---

### 10.3 发布 `/calib_flag` 后提示没有样本

若终端显示：

```text
No valid odometry/laser scan pairs have been collected; calibration is skipped.
```

说明触发标定太早。应先回放 bag，等待：

```text
Data Cnt:1
Data Cnt:2
...
```

增长后，再重新发布：

```bash
rostopic pub -1 /calib_flag std_msgs/Empty "{}"
```

---

### 10.4 提示运动数据秩不足

若出现：

```text
Cannot solve odometry calibration: the collected motions do not identify all 9 matrix parameters.
```

表示：

```text
rank(A) < 9
```

当前采集的运动不能独立确定 `3×3` 校正矩阵中的全部 9 个参数。

常见原因：

```text
有效样本数量太少；
只采集了单一方向直线运动；
缺少左转、右转、不同曲率的运动；
扫描匹配失败导致实际有效样本很少。
```

解决方法：继续回放提供的完整 bag，或采集包含不同运动方式的数据。

---

### 10.5 持续出现 `PI ICP Failed!!!!!!!`

表示当前相邻激光帧没有产生有效匹配。检查：

```text
激光数据是否为空；
雷达量程、角度和有效点数量是否合理；
机器人单帧运动是否过大；
PI-ICP 的 first_guess 是否与实际相对运动相差过多；
TF 时间是否与 LaserScan 时间对应。
```

实现中，PI-ICP 失败的样本不会写入 `Ax≈b`，避免把错误匹配污染最小二乘结果。

---

### 10.6 RViz 中没有路径

确认：

```text
Fixed Frame 设置为 odom；
三个 Path display 都已添加；
Path topic 名称包含末尾下划线；
rosbag 和标定节点仍在运行；
路径话题确实存在。
```

使用命令检查：

```bash
rostopic list | grep -E '(odom|scan|calib)_path_pub_'
```

正确的话题名称是：

```text
/odom_path_pub_
/scan_path_pub_
/calib_path_pub_
```

末尾的 `_` 不能遗漏。

---

### 10.7 RViz 无法显示或报 X11 权限错误

宿主机为 Wayland/Xwayland 环境时，先运行：

```bash
cd /home/zachary/workspace/ROS_NOETIC/docker
./x11_setup.sh
```

脚本会准备 Docker 所需的 X11 cookie。然后确保 Compose 服务正在运行：

```bash
docker compose up -d
```

再从容器运行：

```bash
rviz
```

---

### 10.8 宿主机 VS Code / clangd 报 ROS 或 Eigen 找不到

例如：

```text
'ros/ros.h' file not found
'eigen3/Eigen/...' file not found
```

这是因为 ROS、Eigen、CSM 等编译依赖位于 Docker 容器内，而宿主机的 clangd 未加载容器中的 include 路径。

这种 IDE 静态诊断不等于工程实际无法编译。应以容器内真实构建与测试结果为准：

```bash
catkin build calib_odom
catkin test calib_odom
```
