## 1. 作业目标与数据流

本作业要使用**直接线性最小二乘法**，根据两种相对运动估计机器人里程计的校正矩阵：

- **里程计相对增量**：由 TF 中的 `odom -> base_link` 位姿计算；
- **激光相对增量**：由相邻两帧激光通过 PI-ICP / CSM 扫描匹配计算；
- **标定矩阵**：找一个 `3×3` 矩阵，将里程计增量映射到更接近激光匹配增量的结果。

源码的数据流如下：

```text
/sick_scan + TF(odom -> base_link)
        │
        ▼
cal_delta_distance() ──> odom_increment
        │
        ├──────────────> PIICPBetweenTwoFrames() ──> scan_increment
        │
        ▼
Add_Data(odom_increment, scan_increment)
        │
        ▼
Solve() ──> correct_matrix
        │
        ▼
correct_matrix × odom_increment ──> /calib_path_pub_
```

已完成的函数：

| 文件 | 函数 | 已完成内容 |
|---|---|---|
| `src/calib_odom/src/main.cpp` | `cal_delta_distance()` | 根据相邻两次里程计绝对位姿，计算上一帧机器人局部坐标系下的相对增量，并归一化角度。 |
| `src/calib_odom/src/Odom_Calib.cpp` | `Add_Data()` | 用一组里程计/激光增量写入最小二乘方程 `Ax=b` 的三行观测。 |
| `src/calib_odom/src/Odom_Calib.cpp` | `Solve()` | 通过 Eigen 完整正交分解求解最小二乘问题，并将 9 个未知数还原为 `3×3` 校正矩阵。 |

## 2. 第一步：完成 `cal_delta_distance()`

位置：`src/calib_odom/src/main.cpp` 中的 `cal_delta_distance()`。

### 2.1 输入和输出的含义

输入是当前时刻在全局 `odom` 坐标系下的绝对位姿：

```text
now_pos = [x₁, y₁, θ₁]ᵀ
```

函数内部已保存上一帧绝对位姿：

```text
last_pos = [x₀, y₀, θ₀]ᵀ
```

输出必须是“**当前帧在上一帧机器人坐标系下的相对运动**”：

```text
d_pos = [Δx_local, Δy_local, Δθ]ᵀ
```

### 2.2 不能只做全局坐标相减

下面这个做法不够：

```text
Δx = x₁ - x₀
Δy = y₁ - y₀
```

原因：这仍然是 `odom` 全局坐标系的位移；而后续 CSM 初值和标定模型使用的是机器人相对运动。

正确的推导步骤：

1. 先计算全局坐标系的位置差：

   ```text
   Δp_world = [x₁ - x₀, y₁ - y₀]ᵀ
   ```

2. 用上一帧的朝向 `θ₀`，把这个差值转换到上一帧车体坐标系：

   ```text
   Δp_local = R(θ₀)⁻¹ · Δp_world
   ```

3. 计算角度差：

   ```text
   Δθ = θ₁ - θ₀
   ```

4. 将 `Δθ` 归一化到 `[-π, π]`。

> 思考：二维旋转矩阵 `R(θ)` 将车体坐标转到世界坐标。既然现在要反向从世界坐标转回上一帧车体坐标，就应该使用什么矩阵？它和 `R(θ)` 的转置有什么关系？

### 2.3 手算自检用例

写完后，不运行 ROS，也应先手算这些例子。

#### 用例 A：朝 x 正方向前进

```text
last = [0, 0, 0]
now  = [1, 0, 0]
```

预期局部增量：

```text
[1, 0, 0]
```

#### 用例 B：朝 y 正方向前进

```text
last = [2, 1, π/2]
now  = [2, 2, π/2]
```

机器人朝向世界坐标 y 正方向，因此在自身局部坐标中是“前进 1 米”。预期：

```text
[1, 0, 0]
```

如果结果是 `[0, 1, 0]`，说明没有将世界坐标增量旋转回上一帧机器人坐标系。

#### 用例 C：跨越 ±π 的转向

```text
last_yaw = 179°
now_yaw  = -179°
```

实际转角接近 `+2°`，而不是 `-358°`。这正是角度归一化的必要性。

### 2.4 第一帧处理

第一帧没有前一帧，因此不能构成运动增量。当前代码已经通过 `has_previous_odom_pose_` 做了首帧保护：首帧只用来建立参考位姿并直接返回。

实现时需要保证：

- 参考位姿只在本次调用结束后更新；
- 返回前不会使用未初始化的 `d_pos`；
- 后续每帧都基于上一帧而非原点计算增量。

## 3. 第二步：推导 `Add_Data()` 的 `Ax=b`

位置：`src/calib_odom/src/Odom_Calib.cpp` 中的 `Add_Data()`。

### 3.1 从代码读出矩阵规模

在 `Set_data_len()` 中：

```cpp
A.conservativeResize(len * 3, 9);
b.conservativeResize(len * 3);
```

因此：

```text
A : 3N × 9
x : 9 × 1
b : 3N × 1
```

每一对输入增量提供 3 个标量方程；未知数是一个 `3×3` 校正矩阵的 9 个元素。

### 3.2 写出标定模型

调用处是：

```cpp
correct_inc = correct_matrix * odom_inc;
```

因此建模关系为：

```text
scan_increment ≈ correct_matrix × odom_increment
```

定义：

```text
odom = [ox, oy, oθ]ᵀ
scan = [sx, sy, sθ]ᵀ

M = [m00 m01 m02
     m10 m11 m12
     m20 m21 m22]
```

你需要先亲自在纸上把下式展开成三个标量方程：

```text
scan = M · odom
```

### 3.3 填矩阵前要回答的问题

对每组 `odom`、`scan`：

1. 第一条标量方程对应 `scan` 的哪个分量？
2. 第一条方程需要使用 `M` 的哪三个元素？其余六个未知数的系数是什么？
3. 第二、第三条方程如何对应 `M` 的第二、第三行？
4. 第 `k` 组样本的三行在 `A`、`b` 的哪三个行号？
5. `now_len` 应在填入样本前还是填入样本后递增？为什么？

建议先写出一个通用的块矩阵结构：

```text
A_k = [ ? ? ?  ? ? ?  ? ? ?
        ? ? ?  ? ? ?  ? ? ?
        ? ? ?  ? ? ?  ? ? ? ]

b_k = [ ?
        ?
        ? ]
```

把 `?` 全部换成 `ox`、`oy`、`oθ`、`0` 和对应的激光观测值。确认后再写 C++。

### 3.4 数据数量与数组边界

`is_full()` 的语义是收集到设定数量的数据后允许求解。实现 `Add_Data()` 时要确认：

- 写入的行索引不超过 `A.rows() - 1`；
- 相同的一组数据只写一次；
- 收集到足够数据后不要继续越界写入；
- 只有成功完成扫描匹配的样本才应成为一组观测。

## 4. 第三步：完成 `Solve()`

位置：`src/calib_odom/src/Odom_Calib.cpp` 中的 `Solve()`。

### 4.1 目标

求一个最小二乘解：

```text
min ||A x - b||²
```

得到长度为 9 的向量 `x`，再按照你在 `Add_Data()` 采用的未知数排列顺序还原为：

```text
correct_matrix : 3 × 3
```

### 4.2 数值方法选择

优先研究 Eigen 的 QR 分解接口，例如 Complete Orthogonal Decomposition 或 ColPivHouseholderQR。不要自行直接计算：

```text
(AᵀA)⁻¹Aᵀb
```

原因：显式求逆会降低数值稳定性，特别是观测数据接近共线、旋转不足或里程计增量尺度差别很大时。

### 4.3 写回矩阵时的检查

完成求解后必须核对：

1. `x` 中第 0～2 个元素是否对应 `correct_matrix` 的第一行？
2. 第 3～5 个元素是否对应第二行？
3. 第 6～8 个元素是否对应第三行？
4. 这个约定是否与 `Add_Data()` 中 `A` 的列顺序完全一致？
5. 数据不足、秩亏时，是否应拒绝求解或给出明确提示？

临时单位阵只用于防止未初始化内存被使用；完成作业后，应让正常路径返回真正求得的矩阵。

## 8. 作业实现说明

本节记录本次提交采用的数学模型和实现约定，以便答辩、检查代码或后续修改时核对。

> 前面第 2～4 节保留了原有的推导练习题；以下内容给出本次实际采用的结果与实现约定。

### 8.1 `cal_delta_distance()`：绝对位姿变相对位姿

设相邻两帧中，`base_link` 在 `odom` 中的绝对位姿分别为：

```text
P₀ = [x₀, y₀, θ₀]ᵀ
P₁ = [x₁, y₁, θ₁]ᵀ
```

先计算全局坐标的平移差：

```text
Δp_odom = [x₁ - x₀, y₁ - y₀]ᵀ
```

再将它转换到**上一帧**机器人坐标系：

```text
Δp_local = R(-θ₀) · Δp_odom

R(-θ₀) = [ cos θ₀   sin θ₀ ]
         [-sin θ₀   cos θ₀ ]
```

因此实现为：

```text
Δx_local =  cos θ₀ · Δx_odom + sin θ₀ · Δy_odom
Δy_local = -sin θ₀ · Δx_odom + cos θ₀ · Δy_odom
Δyaw     = atan2(sin(θ₁ - θ₀), cos(θ₁ - θ₀))
```

其中 `atan2(sin(·), cos(·))` 将角度限制在 `[-π, π]`，避免从 `179°` 到 `-179°` 被误判为 `-358°` 的大转角。

首帧没有上一帧，只记录初始位姿、返回零增量；之后始终在完成计算后才更新参考位姿。

完整的二维旋转矩阵推导与坐标系说明参见：[二维坐标变换与旋转矩阵基础.md](二维坐标变换与旋转矩阵基础.md)。

### 8.2 `Add_Data()`：把一组观测写成 `Ax=b`

校正模型定义为：

```text
scan ≈ M · odom

odom = [ox, oy, oθ]ᵀ
scan = [sx, sy, sθ]ᵀ

M = [m00 m01 m02
     m10 m11 m12
     m20 m21 m22]
```

将未知矩阵按行展开：

```text
x = [m00, m01, m02, m10, m11, m12, m20, m21, m22]ᵀ
```

则每一组观测对应 `A` 中连续三行和 `b` 中连续三个元素：

```text
Aₖ = [ox  oy  oθ   0   0   0   0   0   0
       0   0   0  ox  oy  oθ   0   0   0
       0   0   0   0   0   0  ox  oy  oθ]

bₖ = [sx, sy, sθ]ᵀ
```

若当前已有 `k` 组样本（从零计数），就写入：

```text
A 的第 3k、3k+1、3k+2 行
b 的第 3k、3k+1、3k+2 个元素
```

写入完成后才增加样本计数。达到配置的最大样本量后，`Add_Data()` 返回 `false`，调用方不再写入额外样本，也不再把对应增量放进重放校正路径，避免“求解样本”和“路径重放样本”不一致。

### 8.3 `Solve()`：稳定地求解最小二乘

对收集到的前 `N` 组样本，求解：

```text
min ||A x - b||²
```

实现使用 Eigen 的 `CompleteOrthogonalDecomposition`，而不是显式计算：

```text
(AᵀA)⁻¹ Aᵀb
```

后者会放大数值误差。求得的 `x` 按照第 8.2 节的行优先顺序重新填回：

```text
M 的第 0 行 ← x[0..2]
M 的第 1 行 ← x[3..5]
M 的第 2 行 ← x[6..8]
```

此外，代码会拒绝两类无效求解：

1. 没有任何有效样本；
2. 观测矩阵秩小于 9，即运动数据不能唯一识别全部 9 个矩阵参数。

后者常发生于只有单一方向直线运动、转动不足或可用样本过少的情形。收到无效数据时，标定回调会记录错误并保持订阅，不会发布伪造的校正路径。

### 8.4 回调流程中的有效性保护

除三个 TODO 外，实现还保证了观测配对正确：

- 只有 PI-ICP / CSM 返回 `valid` 的帧对才进入 `Add_Data()`；匹配失败不会将里程计初值当成激光观测；
- 即使机器人运动太小而跳过本轮标定，也会推进激光和里程计的参考帧，确保下一次 ICP 所用激光帧对与里程计增量是同一对时刻；
- 平移和角度阈值用绝对值比较，因此后退、右移、顺时针旋转不会被错误丢弃；
- 收到 `/calib_flag` 但尚未收集有效样本时，节点仅报警而不会抛出未捕获异常；
- 标定完成后才取消激光订阅。

## 11. 推荐的检查顺序

1. 先运行 `catkin build calib_odom`，确认编译成功；
2. 再运行 `catkin test calib_odom`，确认矩阵构建和求解的单元测试通过；
3. 回放 bag，观察终端中 `Data Cnt` 是否持续增加；
4. 检查 `odom_path_pub_` 与 `scan_path_pub_` 是否出现；
5. 发布 `/calib_flag`；
6. 检查是否输出 `correct_matrix`，并在 RViz 中比较 `calib_path_pub_` 和另外两条路径。

按这个顺序检查，可以将数学实现错误、构建问题、TF/话题问题、扫描匹配问题和可视化问题区分开。
