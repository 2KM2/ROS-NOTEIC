# 四、放在一起看：什么时候用哪个

> 前三篇各讲一个算法。这一篇只做一件事：**把它们并排放，用实测数字回答"该用哪个"。**
> 所有数字都可以用文中给出的命令原地复现。

## 4.1 一页表格

先把结论摊开。三个算法的差别只有伪代码第 3 行和第 12 行：

| | 第 3 行 取哪个 | 第 12 行 已在 frontier | 容器 | 步数最少 | 代价最小 | 复杂度 |
| --- | --- | --- | --- | --- | --- | --- |
| **BFS** | 最早入队 (FIFO) | 跳过 | `deque` 头取 | ✅ 永远 | ✅ **4 邻域下**<br>❌ 8 邻域 / 有地形代价 | `O(V+E)` |
| **DFS** | 最晚入栈 (LIFO) | 再压一次 | `deque` 尾取 | ❌ | ❌ | `O(V+E)` |
| **Dijkstra** | `g` 最小 | 更短就松弛并重入 | 小顶堆 | ❌ 8 邻域下可能更多 | ✅ 永远（非负边权） | `O((V+E) log V)` |
| *(A\*，隔壁包)* | `g+h` 最小 | 同 Dijkstra | 小顶堆 | ❌ | ✅（h 可采纳） | `O((V+E) log V)` |

**"步数最少"和"代价最小"是两个不同的目标函数**，这是整张表的骨架：

```
depth = 走了几格          <- BFS 优化这个
g     = Σ 每条边的代价     <- Dijkstra / A* 优化这个
```

4 邻域（本包默认）下每条边代价都是 1，两列**合并成一列** —— 所以那一格是 ✅。
一旦允许对角线或加上地形代价，它们就分道扬镳。

## 4.2 三种扩展形状

起点在正中 `(10,6)`，都跑到**第 40 步**。

```bash

  rosrun search_tutorial search_console_demo --algo $a --map empty --size 21 13 \
      --start 10 6 --goal 20 12 --range 40 40 --no-skips
```

**两个不同的形状 = 两个不同的目标函数**，这是全包最重要的一张图：

- **BFS = 正方形**：切比雪夫等距面 `max(|dx|,|dy|) = 常数`。斜着走一步也只算 **1 步**，

### 出堆顺序的对偶性

同一件事还能从数字上看。8 邻域 7×5 空地图，前 22 次出堆：

| | 出堆的 `g` | 出堆的 `步数` |
| --- | --- | --- |
| **BFS** | `… 3.828 → 3.000 …` **不单调** | **单调不减** |
| **Dijkstra** | **单调不减** | `… 4 → 3 …` **不单调** |

```bash
rosrun search_tutorial search_console_demo --algo bfs      --conn 8 --map empty --size 7 5 --no-skips
rosrun search_tutorial search_console_demo --algo dijkstra --conn 8 --map empty --size 7 5 --no-skips
```

**每个算法都严格单调于自己优化的那个量，对另一个量则不然。**
这就是"两个目标函数"在出队序列上的样子，也是各自正确性证明的抓手
（BFS 的见 [01-bfs.md](01-bfs.md) §1.3 引理，Dijkstra 的见 [03-dijkstra.md](03-dijkstra.md) §3.3 推论 1）。

4 邻域下这张表塌成一格：两列都单调不减，因为它们是同一列。

## 4.3 实测数字（4 邻域 = 本包默认）

`--compare` 在同一张图、同一对起终点上跑完四个算法。以下全部是真实输出。

### 空地图 41×25

```bash
rosrun search_tutorial search_console_demo --compare --map empty --size 41 25
```

```
algo        expanded   pushes    stale      peak  steps       cost       ms
BFS             1025     1025        0        26     64    64.0000    0.061
DFS             1025     1985        0       961   1024  1024.0000    0.080   <- 路径比最短路长 1500.0%
Dijkstra        1025     1025        0        26     64    64.0000    0.088
A*(manhat)        65      127        0        63     64    64.0000    0.027
```

三件事：

1. **BFS 和 Dijkstra 每一列都一样**（连 `peak` 都是 26）—— 4 邻域下它们是同一个算法。
2. **DFS 走了 1024 步走完 64 步就能到的路**，`peak 961` 是 BFS 的 37 倍。
   1025 个格子它经过了 1024 个 —— 把空地图当成一条蛇形走廊走了一遍。
   **空地图是最"简单"的地图，DFS 在这里最难看。**
3. `A*(manhat)` 一行 **1025 → 65**。这才是真正的差距所在，见 §4.5。

### 竖墙 41×25

```bash
rosrun search_tutorial search_console_demo --compare --map walls --size 41 25 --seed 7
```

```
algo        expanded   pushes    stale      peak  steps       cost       ms
BFS              861      861        0        25     80    80.0000    0.041
DFS              784     1391      136       472    448   448.0000    0.045   <- 路径比最短路长 460.0%
Dijkstra         861      861        0        25     80    80.0000    0.059
A*(manhat)       638      927      258        71     80    80.0000    0.168
```

注意 `A*(manhat)` 这一行的 `stale = 258` —— **A\* 在 4 邻域下会松弛成功，Dijkstra 不会。**
[03-dijkstra.md](03-dijkstra.md) §3.4 那个"松弛永不成功"的证明用的前提是**出堆的 `g` 单调不减**；
A\* 出堆的是 `f = g + h` 单调不减，`g` 不再单调，所以证明失效。
（这不是 bug，只是 A\* 会先从"看起来有希望"的方向摸过去、再发现更便宜的走法。）

也注意 A\* 在这张图上只把 861 降到 638 —— **墙让启发函数变钝了**，
它以为直着穿过去就行，撞墙才知道要绕。启发函数好不好用取决于地图。

### 迷宫 41×25 —— DFS 唯一不吃亏的场合

```bash
rosrun search_tutorial search_console_demo --compare --map maze --size 41 25 --seed 3
```

```
algo        expanded   pushes    stale      peak  steps       cost       ms
BFS              246      247        0         4    140   140.0000    0.027
DFS              453      453        0         7    140   140.0000    0.016
Dijkstra         247      248        0         4    140   140.0000    0.016
A*(manhat)       180      182        0         3    140   140.0000    0.041
```

**四个算法的 `steps` 和 `cost` 完全一样，连 DFS 都是 140。**
因为完美迷宫是一棵**树**，任意两点之间只有一条简单路径 ——
"最短路"和"随便一条路"是同一条，DFS 想差也差不了。

它多扩展了 `453 - 246 = 207` 个格子（钻进死胡同再退回来），但答案一样好；
`stale = 0` 是因为走廊宽 1，一个格子几乎不会被两个不同的邻居同时发现。

**先看图的结构，再选算法** —— 这一行是全表里最实用的一条。

### 手算规模 8×6

```bash
rosrun search_tutorial search_console_demo --compare --map tiny
```

```
algo        expanded   pushes    stale      peak  steps       cost       ms
BFS               39       39        0         5     12    12.0000    0.003
DFS               27       40        0        14     26    26.0000    0.002   <- 路径比最短路长 116.7%
Dijkstra          39       39        0         5     12    12.0000    0.003
A*(manhat)        13       21        0         9     12    12.0000    0.003
```

小到可以一步步按回车手推。注意 **DFS 反而少扩展了 12 个格子**（27 < 39）——
它撞上终点就停了，运气好。**"扩展得少"不等于"更好"**：它的路径长了一倍多。
拿 `expanded` 当唯一指标是新手最常见的误读。

### 汇总：DFS 有多差（4 邻域）

| 地图 | BFS / Dijkstra 步数 | DFS 步数 | DFS 长了 | DFS 的 frontier 峰值 / BFS 的 |
| --- | --- | --- | --- | --- |
| `empty` 41×25 | 64 | **1024** | **+1500.0%** | 961 / 26 = **37×** |
| `walls` 41×25 | 80 | 448 | +460.0% | 472 / 25 = 19× |
| `random` 41×25 | 64 | 510 | +696.9% | 502 / 27 = 19× |
| `maze` 41×25 | 140 | 140 | **+0%** | 7 / 4 = 1.8× |
| `tiny` 8×6 | 12 | 26 | +116.7% | 14 / 5 = 2.8× |

## 4.4 3000 个随机实例上的统计

`--compare` 是逐张地图看。要回答"这有多常见"，得跑量：

```bash
rosrun search_tutorial search_selfcheck 3000
```

真实输出（未删改）：

```
search_tutorial 自检：3000 个随机实例 + 边界情况
交叉验证对象：独立参考 BFS、astar_tutorial 的 A*(h=0) 和 A*(octile)、回放器

================ 统计（8 邻域，2771 个可解实例）================
BFS 的路径严格比最短路更长 : 65 次 (2.3%)，最差比最优解长 7.93%
Dijkstra 的步数严格比 BFS 多 : 20 次 (0.7%)
DFS 的路径严格比最短路更长   : 2171 次，最差长 1698.7%
=> "BFS 步数最少 != 代价最短" 不是理论上的吹毛求疵，8 邻域随机地图上就是这个频率。

================ 统计（4 邻域 = 本包默认，2737 个可解实例）================
BFS 的路径严格比最短路更长 : 0 次（必须是 0）
Dijkstra 的步数严格比 BFS 多 : 0 次（必须是 0）
=> 4 邻域下每条边代价都是 1，「步数最少」和「代价最小」是同一个目标，
   所以 BFS 和 Dijkstra 的 cost / steps 被逐个实例断言为完全相等。
   这就是默认配置下可以放心用 BFS 的理由。

================ 结果 ================
检查 3084303 项，失败 0 项
全部通过 ✓
```

### 怎么读这四个数字

| 数字 | 含义 |
| --- | --- |
| 4 邻域 **0 次 / 0 次** | **本包默认配置下 BFS 就是最短路算法** —— 不是"差不多"，是逐个实例断言的相等 |
| 8 邻域 BFS **2.3%**，最差 **+7.93%** | 开对角线之后 BFS 开始出错。频率不高，**但表现是"路还是通的、只是长了一点点"，靠眼睛永远发现不了** |
| 8 邻域 Dijkstra 步数多 **0.7%** | 反方向也会发生：Dijkstra 宁可多走一格直线也不肯多走一步 `√2` 的斜线 |
| DFS **2171 / 2771 ≈ 78%** | DFS 在四分之三的实例里更差，最差长 17 倍 |

### 这 308 万项检查在查什么

selfcheck 不是"跑一遍看不崩"，它拿**三份独立实现**对答案：

| 交叉验证对象 | 查什么 |
| --- | --- |
| 一份独立写的参考 BFS | `BFS 的 depth[] 逐格等于最少步数` |
| `astar_tutorial` 的 **A\*(h≡0)** | `Dijkstra 的代价 == A*(zero) 的代价` |
| `astar_tutorial` 的 **A\*(octile)** | `Dijkstra 的代价 == A*(diagonal) 的代价` |
| `TraceReplayer` 回放到底 | 回放出的 `state / g / depth / parent` 和 `nodes()` **逐位相等**，且 seek 幂等 |

外加各算法自己的不变量（`BFS 的 stale_pops 恒为 0`、`DFS 的代价 >= Dijkstra 的代价`、
`三个算法对可达性的判断一致`、§3.4 那三条 4 邻域断言……）。

**三份独立实现给出同一个数字，才敢在文档里写"最优"。**

## 4.5 真正的差距不在这三个算法之间

把 §4.3 空地图那张表再看一眼：

```
BFS             1025      64    64.0000
Dijkstra        1025      64    64.0000
A*(manhat)        65      64    64.0000     <- 扩展数少 15.8 倍，答案一模一样
```

BFS 和 Dijkstra 都**不知道终点在哪**，往所有方向平摊 —— 看 §4.2 那个菱形：
终点在右上角，左下方向也铺了同样多的格子。它们把 1025 个格子全扩展了一遍。

`A*` 只是在第 3 行的排序键上加了一个 `h`：

```
BFS       第 3 行取: 最早入队的
DFS       第 3 行取: 最晚入栈的
Dijkstra  第 3 行取: g     最小的
A*        第 3 行取: g + h 最小的      <- 就这一处
```

**换来 15.8 倍。** 所以本包的正确定位是：

> **BFS / DFS / Dijkstra 是理解那个统一循环的最短路径，
> 而实际要用的是 A\*（以及它的各种变体）。**

`h` 怎么选、什么是可采纳性和一致性、4 邻域为什么该用 manhattan 而不是 octile
（差 962 vs 65！）、Weighted A\* 拿最优性换了什么 —— 全在
[astar_tutorial](../../astar_tutorial/README.md)，那是这个包的续集。

## 4.6 一张选择表

| 你的问题 | 用 | 为什么 |
| --- | --- | --- |
| **4 邻域栅格，无地形代价，要最短路** | **BFS** | `g ≡ depth`，答案和 Dijkstra 相同，`O(V+E)`，不用堆，`stale_pops` 恒为 0 |
| 同上，但地图大 / 要快 | **A\*(manhattan)** | 实测扩展数少一个数量级 |
| 8 邻域，或格子带代价（costmap） | **Dijkstra / A\*** | `g ≠ depth`，BFS 会给出次优路径且看不出来 |
| 边权可能是**负的** | 都不行 → Bellman-Ford / SPFA | Dijkstra 的证明前提是非负边权 |
| 只想知道"通不通"、有几个连通块 | **DFS**（或 BFS，随便） | 任何遍历都对，选实现最简单的 |
| 迷宫这类"路本来就唯一"的图 | 都行，**DFS 也不吃亏** | 树上只有一条简单路径 |
| 分支因子大、深度浅（博弈树、组合搜索） | **DFS** | 栈深 `O(d)` 而 BFS 队列宽 `b^d` —— 这里的结论**别往栅格上推** |
| 拓扑排序 / 强连通分量 / 桥和割点 | **DFS** | Tarjan 那一套建立在 DFS 的递归结构上 |
| 要拿到**所有**格子到起点的距离场 | **BFS / Dijkstra** | A\* 有 `h`，只保证终点那条最优；不带 `h` 的才是完整的距离场 |

最后一行值得多说一句：**"单源最短路"和"点到点最短路"是两个问题。**
势场法、Voronoi 图、DWA 的代价查找表都需要**整张距离场**，那时候 `h` 帮不上忙，
你要的就是 Dijkstra（或 4 邻域下的 BFS）跑到 frontier 抽干为止。

## 4.7 自己动手

一次把三个算法都看一遍（rviz 里）：

```bash
# 终端 1
roslaunch search_tutorial search_demo.launch auto_play:=false \
    map_type:=empty map_width:=20 map_height:=14 map_resolution:=1.0 show_cost_text:=true
# 终端 2
rosrun search_tutorial search_keyboard
```

然后按这个顺序：

| 按 | 看什么 |
| --- | --- |
| `1` 然后一直按 `n` | BFS 一圈圈推出菱形 |
| `3` 然后 `n` | Dijkstra —— **同一个菱形**（4 邻域） |
| `2` 然后 `n` | DFS 一头扎到底，注意终端里刷过去的"已在栈里,DFS再压一次" |
| `c` | 三算法对比表，确认 BFS / Dijkstra 的 cost 逐位相同 |
| `v` 再按 `c` | 切到 8 邻域 —— BFS 那行的 cost 开始比 Dijkstra 大 |
| `v` 后再 `1` / `3` | 正方形 vs 八角形，§4.2 那张图的实物版 |

再找一个 8 邻域下 BFS 确实更差的具体反例：

```bash
rosrun search_tutorial search_console_demo --counterexample
```

（它会打印两张并排的地图和复现命令。注意它**强制用 8 邻域** ——
4 邻域下这种反例不存在，见 [01-bfs.md](01-bfs.md) §1.4。）
