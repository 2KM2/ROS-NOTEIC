# 一、BFS：一层一层往外推

> 本包默认 **4 邻域**：机器人只能上下左右走，**不走对角线**。
> 这一篇的所有结论都基于这个前提，而这个前提比它看起来重要得多 —— §1.4 专门讲为什么。

## 1.1 栅格地图就是一张图

"栅格路径规划"和教科书上的"图上最短路"是同一个问题，只是长得不像：

| 图的概念 | 4 邻域栅格里是什么 |
| --- | --- |
| 顶点 V | 每个**空闲**格子。本包用一维下标 `id = y * width + x` 编号（`GridMap2D::toId`） |
| 边 E | 每个格子和它的上/下/左/右四个邻居相连，所以 `|E| ≤ 4|V|`（边界格子更少） |
| 边代价 c | **全部是 1**。见 `graph_search.cpp` 里 `kDX/kDY` 方向表 —— 4 邻域只取前 4 个方向 |
| 障碍 | 不是顶点，等于把它和它所有的边一起从图里删掉 |

**"边代价全部是 1"就是这一篇能成立的全部理由。** 一张所有边权相等的图叫
**无权图（unweighted graph）**，无权图上的最短路有一个特别便宜的算法，就是 BFS。

```
   4 邻域                       8 邻域（本包不默认用）
     ↑                           ↖ ↑ ↗
   ← · →      每条边代价 1        ← · →     直边 1，斜边 √2
     ↓                           ↙ ↓ ↘
```

顺便记住 `graph_search.cpp` 里那句注释的分量：

```cpp
static const int kDX[8] = {1, -1, 0, 0, 1, 1, -1, -1};
static const int kDY[8] = {0, 0, 1, -1, 1, -1, 1, -1};
const int num_dirs = cfg_.use_8_connected ? 8 : 4;   // 默认 4 -> 只取前 4 个
```

前 4 个是直走，后 4 个是斜走，**顺序不能改**。一旦把某个斜方向挪进前 4 个，
"4 邻域"就悄悄变成了"允许对角线"，而所有的数字看起来还都很正常。

## 1.2 算法：把 frontier 当队列用

统一伪代码在 `graph_search.h` 顶部，13 行。BFS 只需要在两处做出选择：

| 伪代码行 | BFS 的选择 |
| --- | --- |
| 第 3 行 `item = frontier.取出一个` | **取最早进来的那个**（FIFO 队列头） |
| 第 12 行 `nb 已经在 frontier 里了怎么办` | **什么都不做，跳过** |

代码里就是这两处：

```cpp
// graph_search.h, Frontier::pop()                          [伪代码 3]
if (algo_ == Algorithm::kBfs) {
  const FrontierItem it = deque_.front();  // 最早进来的 -> BFS（FIFO 队列）
  deque_.pop_front();
  return it;
}
```

```cpp
// graph_search.cpp                                         [伪代码 12]
case Algorithm::kBfs:
  // BFS：已经进过队列，说明有人比我更早（或同层）发现它，
  // 那条路的步数一定 <= 我这条。既然只关心步数，就没必要再看一眼。
  // 这一行就是 BFS "每个格子只入队一次" 的全部原因。
  ev.action = NeighborAction::kSkippedSeen;
  break;
```

第 12 行的"跳过"带来两个后果，都很值得记住：

1. **每个格子恰好入队一次**。所以 `stats.stale_pops` 恒为 0（selfcheck 里有这条断言），
   队列里也永远不会出现同一个格子的两份条目。
2. **不需要堆，也不需要 decrease-key**。`std::deque` 就够。复杂度 `O(V + E)`，
   比 Dijkstra 的 `O((V+E) log V)` 少一个 log。

一层一层往外推是什么样子 —— 21×13 空地图，起点在正中 `(10,6)`，跑到第 40 步：

CLOSED 区域（`x`）是一个**菱形**，绿色 frontier（`o`）是菱形的边框。
菱形 = 曼哈顿距离的等距面 `|dx| + |dy| = 常数` —— 因为 4 邻域下走 `k` 步能到的
格子正好就是 `|dx| + |dy| ≤ k`。**扩展形状直接就是"步数"这个度量的等高线**，
这是 BFS 最直观的一面：它按"离起点几步"排队。

## 1.3 为什么 BFS 保证步数最少

只有一个命题需要证，但要证清楚。

**记号**：`d(v)` = 从起点 `s` 到 `v` 的真实最少步数（不可达则 `∞`）；
`depth[v]` = 算法写进节点里的值。

**引理（队列的单调性）**：主循环任何时刻，队列里所有条目的 `depth` 从头到尾**单调不减**，
且最大值和最小值相差**至多 1**。

*证明*：对循环轮数归纳。初始队列只有 `{s}`，`depth = 0`，成立。
设当前队列的 depth 序列为 `d, …, d, d+1, …, d+1`。这一轮从**头部**弹出的必然是个 `d`，
它把新发现的邻居以 `depth = d+1` 追加到**尾部** —— 尾部原本就是 `d+1`（或队列本来就只剩 `d`，
此时新元素成为唯一的 `d+1`）。两种情况下单调性和"至多相差 1"都保持。∎

**推论 1**：出队的 `depth` 序列单调不减。

**定理**：每个格子 `v` 出队时，`depth[v] = d(v)`。

*证明*：对 `d(v)` 归纳。

- `d = 0`：只有 `s`，`depth[s] = 0`。
- 设所有 `d(u) ≤ k` 的格子都满足 `depth[u] = d(u)`，取任意 `d(v) = k+1`。
  存在最短路 `s → … → u → v`，其中 `d(u) = k`。由归纳假设 `u` 出队时 `depth[u] = k`；
  `u` 出队时会检查 `v`，于是 `v` 在此刻之前就已入队（或就在此刻入队），且
  入队时写的 `depth[v] = depth[父] + 1`。

  剩下要排除的是：`v` 会不会**更早**被某个 `depth` 更大的格子发现，从而写下过大的值？
  不会 —— 由推论 1，出队顺序的 depth 单调不减，任何在 `u` 之前出队的格子 `w` 都满足
  `depth[w] ≤ k`，所以 `v` 若由 `w` 发现，得到的是 `depth[v] = depth[w] + 1 ≤ k+1`。
  又因为 `d(v) = k+1` 是真实下界，`depth[v] ≥ k+1`。两边一夹，`depth[v] = k+1`。∎

请注意这个证明里**完全没有用到边代价**，用到的只有"每条边算 1 步"。
所以 BFS 求的**永远**是步数最少 —— 不管边代价是多少。这既是它的强项，也是它的陷阱，
见下一节。

### 一个能省的地方，和一个不能省的地方

BFS 的 `depth[v]` 在**第一次发现**时就已经是最终值了（上面证明的直接推论）。
所以对 BFS 来说，**"入队时就判断是不是终点、然后直接返回"是正确的**。

本包**没有**这么写 —— 第 6 行的终点判断放在**出队之后**：

```
5      落定 item: state[cur]=CLOSED, 把 g/depth/parent 写进节点
6      if cur == goal:  沿 parent 回溯出路径，结束
```

因为这段主循环要同时给 Dijkstra 用，而 **Dijkstra 绝对不能在入堆时返回**
（那时终点的 `g` 只是某一条路的代价，不一定最优 —— 见 [03-dijkstra.md](03-dijkstra.md) §3.3）。
统一伪代码选了"对三个算法都正确"的那个写法，代价是 BFS 多绕一圈。

这是读这个包时值得留意的一类细节：**共用代码时，正确性要按最严的那个算法来取。**

## 1.4 「步数最少」什么时候不等于「路径最短」

这是本包最重要的一节，也是 `graph_search.h` 里那句 `见 doc/01-bfs.md 的 §1.4` 指向的地方。

BFS 优化的是 `depth`（步数），Dijkstra 优化的是 `g`（几何代价）。**这是两个不同的目标函数。**

```
depth = 走了几格                    <- BFS 优化这个
g     = Σ 每条边的代价              <- Dijkstra 优化这个
```

### 4 邻域：两个目标是同一个

每条边代价都是 1，于是对每个节点

```
g(v) = 1 × depth(v) = depth(v)
```

**两个目标函数逐点相等**，"步数最少"和"代价最小"就是同一件事。结论：

> **4 邻域下 BFS 是一个正确的最短路算法**，而且比 Dijkstra 便宜（不用堆）。

这不是嘴上说说，selfcheck 逐个实例断言了四条：

```cpp
check(std::fabs(bc - dc) < 1e-6,                    "4 邻域下 BFS 的代价 == Dijkstra 的代价");
check(bfs.stats().path_steps == dij.stats().path_steps, "4 邻域下 BFS 的步数 == Dijkstra 的步数");
check(depth_eq_g,                                    "4 邻域下逐格 g == depth");
check(dij.stats().stale_pops == 0,                   "4 邻域下 Dijkstra 的 stale_pops 也是 0");
```

实测（`rosrun search_tutorial search_selfcheck 3000`）：

```
================ 统计（4 邻域 = 本包默认，2737 个可解实例）================
BFS 的路径严格比最短路更长 : 0 次（必须是 0）
Dijkstra 的步数严格比 BFS 多 : 0 次（必须是 0）

检查 3084303 项，失败 0 项
```

**308 万项检查、0 失败。** 4 邻域下这两个算法给出同一个最优值，是被机器验证过的。

（顺便解释一下上面第四条断言为什么成立，它是个漂亮的小结论：
单位边权下 Dijkstra 的**松弛永远不会成功**。出堆的 `g` 单调不减，弹出 `g = k` 的节点时，
任何已在堆里的邻居 `v` 都是从某个 `g ≤ k` 的节点发现的，所以 `g[v] ≤ k+1`；
而新路径给出 `g_new = k + 1 ≥ g[v]`，不严格更小。于是既不换父亲、也不重复入堆 ——
**堆退化成了一个 FIFO 队列**。这就是"4 邻域用 BFS 就够了"的机器可验证版本。）

### 那为什么还要学 Dijkstra？

因为 `g = depth` 这个等式**只在单位边权下成立**，一旦边代价不全为 1 就崩。两种常见的崩法：

#### 崩法一：允许对角线（8 邻域）

斜走一步的几何长度是 `√2 ≈ 1.414`，不是 1。于是设某条路走了 `s` 步直线、`d` 步斜线：

```
步数 = s + d          <- BFS 优化这个
代价 = s + √2·d       <- Dijkstra 优化这个
```

假设 BFS 找到的最少步数是 `k`，它选了一条 `(s₁, d₁)`，`s₁ + d₁ = k`。
另有一条路多走一步：`(s₂, d₂)`，`s₂ + d₂ = k + 1`。什么时候第二条**反而更短**？

```
s₂ + √2·d₂  <  s₁ + √2·d₁
```

令 `Δ = d₁ - d₂`（第一条多用了 Δ 个斜线）。由步数关系 `s₂ - s₁ = 1 + Δ`，代入化简：

```
1 + Δ < √2·Δ   =>   Δ·(√2 - 1) > 1   =>   Δ > 1/(√2-1) ≈ 2.414   =>   Δ ≥ 3
```

**只要存在一条路"多走 1 步、但少用 3 个斜线"，BFS 就会输。**
最小的例子：3 个斜线（`3√2 ≈ 4.243`）换成 4 步直线（`4.000`）—— 多走一步，反而短了 0.243。

（这个推导和 [astar_tutorial/doc/01-dijkstra.md](../../astar_tutorial/doc/01-dijkstra.md) §1.2
是同一个，那边是从 A* 的视角写的，可以对照。）

有障碍强迫你在"斜着挤过去"和"绕个直角"之间做选择时，这种局面完全会出现。
本包有个程序专门去找：

```bash

```

真实输出（14×10 随机地图，试了 276 张找到）：

8 邻域下这有多常见？selfcheck 的统计（2771 个可解实例）：

```

```

**2.3%**。不高，但也绝不是"理论上的吹毛求疵"，而且这种 bug 的表现是
"路径还是通的、还是能走、只是长了一点点" —— 靠眼睛永远发现不了。

还有一个更隐蔽的情况：**BFS 可能步数和 Dijkstra 打平，代价却更大**。
因为在所有"步数最少"的路径中，BFS 返回的是**任意一条**（取决于方向表顺序和入队时机），
它压根不在这些路径里面挑最便宜的。

#### 崩法二：非单位边代价（地形代价）

即使保持 4 邻域，只要给格子加上代价 —— 草地 2、公路 1、泥地 5 —— 边权就不再相等，
BFS 立刻失效，而且这次连 `Δ ≥ 3` 这种"要凑巧才出错"的余地都没有：
一条 3 步的泥路（代价 15）会被 BFS 选中，而 5 步的公路（代价 5）才是对的。

**Dijkstra 对任何非负边权都成立。** 这就是它值得学的地方。
（负权会让 Dijkstra 崩掉，反例和为什么见
[astar_tutorial/doc/01-dijkstra.md](../../astar_tutorial/doc/01-dijkstra.md) §1.4。）

### 一张判断表

| 场景 | 边代价 | 用 BFS 对吗 | 为什么 |
| --- | --- | --- | --- |
| **4 邻域，无地形代价**（本包默认） | 全为 1 | ✅ **对，而且更快** | `g ≡ depth`，两个目标同一个 |
| 8 邻域 | 1 和 √2 | ❌ 步数最少但可能更长 | `Δ ≥ 3` 时输，实测 2.3% |
| 4 邻域 + 地形代价 | 任意非负 | ❌ 彻底不对 | `g ≠ depth` |
| 只想知道"通不通" | 无所谓 | ✅ 对 | 连 DFS 都对，见 [02-dfs.md](02-dfs.md) |

## 1.6 复杂度和它的真实含义

`O(V + E)`，4 邻域下 `E ≤ 4V`，所以就是 **`O(V)`** —— 每个格子处理一次，每条边看一次。

但 `V` 是**格子数**，随分辨率的**平方**增长：分辨率提高一倍，格子数变 4 倍。
这是栅格法的根本代价，跟用哪个算法无关。

而且 BFS（和 Dijkstra 一样）**不知道终点在哪**，它往所有方向平摊。看 §1.2 那张菱形图：
终点在右上角 `G`，但左下方向也铺了同样多的格子。41×25 空地图上的实测：

```
algo        expanded   pushes    stale      peak  steps       cost       ms
BFS             1025     1025        0        26     64    64.0000    0.038
Dijkstra        1025     1025        0        26     64    64.0000    0.083
A*(manhat)        65      127        0        63     64    64.0000    0.025
```

**1025 → 65，扩展数少了 15.8 倍，代价一模一样。** 那一行 `A*(manhat)` 就是
